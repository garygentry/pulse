# Deep health

This runbook is where the `runbook_url` on a **deep-health** functional alert lands. For each service
that declares a deep-health probe, the alerting transform emits **one critical `DeepHealthFailed`
rule** whose expression is the estate's own declared condition (for example `camera_count < 6`),
bound to that service's `pulse_deep_health` series.

This is the **functional-value** signal — "the service answered, and its answer is unhealthy." It is
distinct from **probe reachability** (`DeepHealthProbeFailed` / `DeepHealthProbeStale`), which lives
in the [availability runbook](/availability/). If both fire, reachability comes first: a failing or
stale probe means the mapped values feeding this rule cannot be trusted.

The rule is generated by `stack/alerting/src/transform/deep-health-rules.ts`; the slug comes from
`RUNBOOK_SLUGS.deepHealth` in `stack/alerting/src/constants.ts`.

## When this fires

- **DeepHealthFailed** (critical) — the service's **declared** deep-health expression holds true for
  ~1 scrape cycle. The exact condition is per-service (whatever the estate declared as
  `alertExpression`), bound to `pulse_deep_health{service=…}`. The `service` and `host` labels name
  the affected service and host.

## Triage

**Verify (content):** first rule out a reachability problem — a stale probe makes this rule fire on
stale data. From the engine host:

```bash
cd stack/compose
docker compose run --rm --entrypoint sh alertmanager -c \
  "wget -qO- 'http://victoriametrics:8428/api/v1/query?query=pulse_deep_health_up'"
docker compose run --rm --entrypoint sh alertmanager -c \
  "wget -qO- 'http://victoriametrics:8428/api/v1/query?query=time()-pulse_deep_health_last_scrape_seconds'"
```

`pulse_deep_health_up == 1` and a small last-scrape age mean the probe is healthy and the functional
failure is **real** — proceed. Otherwise fix reachability first via [availability](/availability/).

**Verify (content):** read the mapped health values the declared expression evaluates, to see exactly
which measure breached:

```bash
docker compose run --rm --entrypoint sh alertmanager -c \
  "wget -qO- 'http://victoriametrics:8428/api/v1/query?query=pulse_deep_health%7Bservice%3D%22SERVICE%22%7D'"
```

Compare the returned series against the service's declared threshold (the `alertExpression` in the
estate) to confirm the breach and its magnitude.

## Remediate

Remediation is service-specific — the declared expression encodes what "healthy" means for that
service, so recovery means restoring the underlying measure.

#### Step 1 — Restore the service's functional health

Act on the concrete measure the mapped values identified (e.g. bring a missing camera feed back so
`camera_count` recovers, restart a degraded worker, clear a stuck queue). This happens on or against
the **monitored service**, not the engine.

**Command**

```bash
# On the service host — example shape; the real action is whatever restores the declared measure.
docker compose -f /path/to/service/compose.yml restart SERVICE
```

**Verify (content):** the mapped value returns to its healthy range and the alert clears. Re-run the
`pulse_deep_health{service="SERVICE"}` query above and confirm the declared expression no longer holds
(the value is back on the healthy side of the threshold) — judge by the measured value, never by the
restart's exit code.

**Rollback:** none — restoring service health has no state to undo. If your action regressed the
service, revert it on the host (re-pin the prior image / `git checkout` the service compose) and re-up.

#### Step 2 — If the threshold is wrong, re-declare and re-render

If investigation shows the service is genuinely healthy and the **declared expression** is
mis-calibrated (too tight), correct it in the estate and re-render the rules rather than muting the
alert.

**Command**

```bash
# Edit the service's deep-health alertExpression in the estate, then:
( cd examples/reference && "$PULSE_BIN" render )
bun run alerting:render examples/reference/estate examples/reference/rendered
```

**Verify (content):** the regenerated `DeepHealthFailed` rule carries the corrected expression —
`grep -A3 DeepHealthFailed examples/reference/rendered/vmalert/rules/deep-health.yml` shows the new
threshold; load it into vmalert and confirm the rule no longer fires against healthy data.

**Rollback:** `git checkout -- examples/reference/` restores the prior estate and rendered rules.
