# Backup freshness

This runbook is where the `runbook_url` on a **backup-freshness** alert lands. For each service that
declares `backup_freshness`, the alerting transform emits three per-service rules keyed on the
freshness series — `pulse_backup_freshness_age_seconds` and `pulse_backup_freshness_up` — delivered by
the per-host [command-exporter](/command-exporter/).

The rules are generated by `stack/alerting/src/transform/backup-rules.ts`; the slug comes from
`RUNBOOK_SLUGS.backupFreshness` in `stack/alerting/src/constants.ts`. To **enroll** a new service's
backups (declare + wire), use the [backup enrollment runbook](/backup-enrollment/); this runbook is
for responding when an enrolled backup alerts.

## When this fires

- **BackupStale** (warning) — `pulse_backup_freshness_age_seconds > threshold`: the latest backup is
  older than the service's declared threshold.
- **BackupCritical** (critical) — age `> 2× threshold`: the backup is badly stale (the transform
  derives critical as twice the stale threshold).
- **BackupNoData** (warning, `for: 15m`) — `pulse_backup_freshness_up == 0 or absent(…)`: the freshness
  signal is missing — the command-exporter is not emitting it for this service.

The `service` label names the affected service.

## Triage

**Verify (content):** read the freshness series the rules key on. From the engine host:

```bash
cd stack/compose
# Backup age in seconds for the service (compare against its declared threshold):
docker compose run --rm --entrypoint sh alertmanager -c \
  "wget -qO- 'http://victoriametrics:8428/api/v1/query?query=pulse_backup_freshness_age_seconds%7Bservice%3D%22SERVICE%22%7D'"
# Is the freshness signal present at all? (0 or empty ⇒ BackupNoData territory):
docker compose run --rm --entrypoint sh alertmanager -c \
  "wget -qO- 'http://victoriametrics:8428/api/v1/query?query=pulse_backup_freshness_up%7Bservice%3D%22SERVICE%22%7D'"
```

A large age confirms `BackupStale`/`BackupCritical`; an absent or `0` `_up` confirms `BackupNoData` —
which is a **signal** problem (the exporter), not necessarily a backup problem.

**Verify (content):** on the service host, confirm the actual backup and the command that reports its
freshness:

```bash
# On the service host — inspect the real backup artifact and the freshness command:
ls -l --time-style=full-iso /path/to/backups | tail    # newest backup timestamp
# Run the service's backup_freshness command manually and read its output (per command-exporter):
```

This separates a genuinely-stale backup (fix the backup job) from a broken freshness signal (fix the
exporter).

## Remediate

#### Step 1 — Restore a stale backup (BackupStale / BackupCritical)

If the backup is genuinely old, the backup **job** failed or stopped. Fix and re-run it on the service
host so a fresh artifact lands and its age resets.

**Command**

```bash
# On the service host — re-run the backup job (name per your estate), then confirm a fresh artifact:
systemctl start SERVICE-backup.service    # or the job's own invocation
ls -l --time-style=full-iso /path/to/backups | tail
```

**Verify (content):** the age series drops back under the threshold. Re-run the
`pulse_backup_freshness_age_seconds{service="SERVICE"}` query above after the exporter's next scrape
and confirm the value is below the declared threshold — judge by the age resetting, not by the job
command's exit code.

**Rollback:** none — a fresh backup is the desired state. If the re-run produced a bad artifact,
address the backup job itself on the host.

#### Step 2 — Restore the freshness signal (BackupNoData)

`BackupNoData` means the command-exporter is not emitting `pulse_backup_freshness_*` for the service —
a missing/failing freshness command or a stopped exporter. Repair the exporter per the
[command-exporter runbook](/command-exporter/).

**Command**

```bash
# On the service host — confirm the command-exporter is running and its command resolves:
systemctl status pulse-command-exporter    # name per your enrollment
# Then re-scrape and confirm the series returns (from the engine host):
```

**Verify (content):** `pulse_backup_freshness_up{service="SERVICE"}` returns `1` (re-run the triage
query), and `BackupNoData` clears after the `for: 15m` grace once the signal is flowing.

**Rollback:** if a command/exporter config change didn't help, `git checkout` the estate/exporter
config you edited, re-render, and re-apply.
